# 官网整体规划

本文维护长期目标、能力地图和阶段出口；实际顺位、活跃批次与停止线见[当前规划](current.md)，子专题归属与状态来源统一见[功能与目标索引](../features/README.md)。2026-11-01 整理既有规划，不增加产品范围或改变开发顺序。

## 产品目标与范围

RadishX 是 Radish 系列项目的官网与统一入口。访客应能理解各项目用途、区分当前成果与长期方向，并找到已核实的公开站点、文档和仓库。首页、项目详情、Mascot 与 About 共同承担展示与导航；PC、移动端和可访问性都是交付目标。

沿用 Vite、React、TypeScript 与静态站点交付。`radishx.com` 为 canonical，`www.radishx.com` 为兼容入口；项目独立子域不属于官网业务路由。官网不承载各产品的业务、登录、后台、数据库或服务端 API，不以本地代码完成推断产品已发布。

## 阶段与出口

阶段说明交付顺序，能力专题可以跨阶段；沿用既有 craft Phase、R2.1、R2.2、Q01–Q09 等标识，不另造一套任务编号。

| 交付范围 | 出口与后续关系 |
| --- | --- |
| 首版与历史视觉基线 | 保留对应日期的页面、设计与 QA 证据；被替代的 craft / 灰玉批次不作为当前页面要求 |
| R2.1 设计评审 → R2.2 页面整合 | 按页面范围核对桌面 / 移动与交互，区分 Pencil 静态稿、React 实现、截图确认和剩余设计源回填；由[整体美化目标](../features/site-design-refinement.md)统筹 |
| 内容维护、质量与 SEO | 内容核验可独立推进；质量问题按现有 Q 编号验收，SEO 的输出、依赖与回退方案确认后才实施；见[质量目标](../features/site-quality-and-public-content.md) |
| 发布与持续维护 | 有明确候选、范围和授权后执行发布，并核验线上版本、路由与域名；本地构建或历史 smoke 不构成当前发布证据 |

以上是既有工作的组织关系，具体下一步只由 current 排序。新页面、正式素材、下载或活动能力按现有专题的进入条件单独评估。

## 整体完成口径

- 内容：项目事实带来源和核验日期；公开入口与实际能力一致，未确认项可见。
- 页面：指定批次的主路径、失败 / 空态、键盘与双端验证成立；局部页面完成不代表全站整合完成。
- 品牌：设计确认、素材授权、Web 派生文件、Pencil 与 React 对照分别留证；展示授权不自动包含下载或外部分发。
- 质量与发布：问题修复、静态 / 浏览器检查、线上核验分别记录；未发布或未验环境不得归为已完成。

持续维护的大专题只声明已交付基线及剩余范围，不按文件数、勾选项数计算产品完成率。具体任务、标准与证据来源见[规划与进度规则](../development/agent-collaboration.md#规划层级与进度来源)。
