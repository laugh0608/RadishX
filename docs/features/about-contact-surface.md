# About 联系区

状态：下一开发目标  
最后更新：2026-06-14

## 目标

把 `/about` 打磨成 RadishX 的稳定联系、社交媒体、仓库入口和域名边界页面，让访问者能快速找到联系方式、公众号二维码、GitHub 仓库和未来项目入口状态。

## 背景

About 页已完成首版实现，并接入微信公众号二维码 Web 图。下一步重点不是新增外部服务，而是整理页面节奏、联系信息层级、仓库入口和域名边界，让桌面和 390px 移动端都更容易扫读。

## 范围

- `/about` 页面整体信息层级。
- 联系方式：QQ、Email、GitHub 主页、个人主页。
- 微信公众号二维码和说明。
- 五个 GitHub 仓库入口。
- `radishx.com`、`www.radishx.com` 和四个未来项目域名边界。
- About 页相关结构化数据和样式。

## 不做

- 不新增未确认社交媒体或第三方服务。
- 不把微信公众号二维码移到首页首屏。
- 不修改域名策略或 Vercel 配置。
- 不新增表单、后端 API、订阅系统或数据库。
- 不引入未审核图片。

## 设计要求

- 桌面端应形成清晰的联系方式主列、二维码视觉点和仓库 / 域名分区。
- 移动端优先单列可读，长邮箱、URL、仓库名和域名不能溢出。
- 二维码区域要清楚，但不能压过联系方式和仓库入口。
- 外链入口需要可点击区域足够大，状态和目的明确。
- 页面文案保持克制，不写成组织宣传长文。

## 开发任务

1. 梳理 `/about` 当前 section 顺序和信息密度，确认是否需要拆分或重排。
2. 优化联系方式展示，确保长文本换行、复制 / 访问意图清楚。
3. 优化微信公众号二维码区域，确认图片尺寸、说明文字和移动端留白。
4. 优化 GitHub 仓库入口，让 RadishX 与四个项目的角色差异更容易扫读。
5. 优化域名边界区，继续明确未来子域名不是当前官网 Vercel 路由。
6. 更新对应文档、开发日志和必要验证记录。

## 验证

- `npm run build`
- 桌面视口检查 `/about`，建议 `1440x900`。
- 移动视口检查 `/about`，建议 `390x844`。
- 检查联系方式、二维码图片、GitHub 链接和域名卡片无横向溢出。
- 检查外链 `rel`、可访问名称和触控目标。
- 检查页面 error console。

## 完成标准

- `/about` 在桌面和 390px 移动端信息层级清楚。
- 联系方式、二维码、仓库入口和域名边界都能在一页中自然扫读。
- 长文本和按钮不溢出、不重叠。
- 文档和开发日志同步记录结果。

## 后续事项

- 如果未来新增公开社交账号，先确认账号稳定性和展示优先级。
- 如果需要联系表单，单独建立目标文档并确认后端和隐私边界。
- 如果四个项目独立站上线，再回到域名区更新访问状态。
