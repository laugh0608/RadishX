# 素材治理目标

状态：持续执行，Seasonal 活动图评估与项目视觉素材准入清单已完成
最后更新：2026-06-17

## 目标

建立 RadishX 官网素材从候选、审核、Web 优化、页面接入到后续替换的稳定流程，避免未经审核图片、外部参考图或不清晰版权素材进入正式页面。

## 背景

RadishX 已接入首批 Mascot / About 图片和三个项目详情页 Web 图。首页首屏已使用已审核可爱Q版站姿图作为 Radish Orbit 中心视觉锚点。Mascot 表情拆分、缩略图命名和下载政策已完成当前阶段评估，项目 Logo、真实截图、视频和 RadishMind 自有视觉的准入字段已拆分到独立目标文档，后续仍等待新的正式候选素材。

## 范围

- `assets/` 中候选素材。
- `public/images/` 中已审核公开 Web 资源。
- `docs/assets/materials.md` 中素材清单、审核状态和版权口径。
- 页面数据层中图片来源、用途、使用边界和后续需求。

## 不做

- 不覆盖原始素材。
- 不批量裁切、压缩、重采样或转换格式，除非用户确认。
- 不修改兄弟项目素材或代码。
- 不把外部产品参考截图作为官网项目素材。
- 不提供下载入口或自由复用声明，除非版权口径单独确认。

## 准入规则

- 正式页面使用前，素材必须先记录到 `docs/assets/materials.md`。
- 进入 `public/images/` 的图片必须是 Web 优化版本，不直接使用原始候选图。
- 每个项目详情页素材必须说明 `Asset source`、`Usage boundary` 和 `Next material need`。
- 概念图、历史 UI baseline、代码内视觉和真实截图必须在页面文案中区分。
- 视频接入前必须确认来源、压缩、字幕 / 水印、移动端降级图和加载策略。

## 开发任务

- 后续新增素材时先更新审核清单，再生成 Web 版本。
- 为项目 Logo、截图和视频分别记录来源、用途、风险和接入结论。
- 四项目正式 Logo、截图、视频或 RadishMind 自有视觉出现候选时，先按 [项目视觉素材准入准备](project-visual-asset-readiness.md) 补齐字段，再判断是否生成 Web 版本。
- Mascot 新图进入页面前同步更新 Mascot 目标文档。
- Mascot 单张表情如未来进入页面，先建立拆分清单、命名规则、授权边界和下载口径，再生成单张 Web 文件。
- 首页主视觉变化后，记录是否影响 Open Graph 图。

## Seasonal 活动图准入

`assets/avatars/seasonal/` 当前不直接进入官网长期页面。未来如需使用，必须先确认：

- 活动目标：新春祝福、元旦彩蛋、跨年运营、年末回顾等具体场景。
- 活动窗口：明确上线日期、下线日期和过期后处理方式。
- 页面位置：首页临时活动 band、`/mascot` 顶部活动条、节日彩蛋、社交运营图或活动归档；不能默认进入长期 Gallery 或常驻 Hero。
- 文案边界：只表达节日问候或一次性活动，不承诺项目上线，不声明素材可自由复用，不开放下载。
- 授权边界：确认生成来源、字体 / 文案使用权、公开运营传播范围、是否允许二次裁切和撤回策略。

## 验证

- `npm run build`
- 本地检查新增 `public/images/` 资源返回 `200`。
- 视觉改动时检查桌面和 390px 移动端。
- 检查图片尺寸、格式、`alt`、加载状态和主体裁切。
- 执行 `git diff --check`。
- 纯文档复核类变更执行 `git diff --check`，不要求启动本地浏览器 smoke。

## 完成标准

- 新素材有明确来源、用途、风险、结论和文件路径。
- 原始素材保留在 `assets/`，公开版本进入 `public/images/`。
- 页面、素材文档和目标文档口径一致。
- 未审核素材不进入正式页面。
