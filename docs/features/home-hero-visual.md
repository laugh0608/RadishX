# 首页首屏与主视觉

状态：灰玉首页 Hero 项目舞台已实现并通过双端复核
最后更新：2026-09-06

## 后续目标与适用范围

项目舞台使用已审核素材与代码内示意，不接入实时动态或产品运行数据。静态计数、HUD 文案和项目短定位的后续复核见 [官网质量与对外表达收口](site-quality-and-public-content.md)；不把既有展示描述为实时产品能力。

## 目标

让首页首屏以一个可切换的项目内容舞台表达 RadishX 项目矩阵，并在桌面与移动端提供清楚、可操作的项目入口。

## 背景

历史实现采用中心角色与五项目 orbit，并在首屏展示素材状态槽。`radishx-site-v1.pen` 四轮校正后确认改用单项目内容舞台：首帧展示 Radish 社区动态和成员角色，五个项目作为底部索引切换，避免把不存在的组织关系画成中心辐射图。

## 范围

- `/` 首页首屏纯标题、CTA、项目内容舞台和五项目索引。
- Radish、RadishCatalyst、RadishFlow、RadishMind、RadishLex 五种舞台视觉。
- 移动端品牌与菜单 Header、单列 Hero 和横向项目索引。
- 首页相关 metadata 和 Open Graph 图的后续替换判断。

## 不做

- 不接入未经审核的图片；项目图片继续遵循 `docs/assets/materials.md` 的用途边界。
- 不把代码内自有示意图声明为真实产品截图。
- 不把 Open Graph 图频繁替换为尚未稳定的临时视觉。
- 不复刻 Radish WebOS 或 Console 管理后台结构。

## 当前实现

- Hero 使用单项目内容舞台，Radish 为默认首帧，项目索引切换对应视觉与入口。
- 项目索引使用 `tablist` / `tab` / `tabpanel` 语义，支持点击、方向键、`Home` 与 `End` 键切换。
- 顶部 `Projects` 导航在首页 `/#projects` 锚点和五个项目详情页中都保持 active 状态。
- 首页正文使用不对称生态图谱而非重复 band：Radish 社区轨道、RadishCatalyst 工业场景、RadishFlow 流程蓝图、RadishMind 节点网络、RadishLex 中文输入路径。
- Hero 不再承载素材治理状态槽；素材准入信息保留在文档和项目详情页。
- 移动 Header 使用 44px 菜单按钮，导航和主题切换集中在弹出面板；共享 Header 在页面深滚动位置保持 sticky。
- 当前 Open Graph 图使用已确认完全体设定图生成，已完成本地视觉评估；它包含 RadishX 标题、项目矩阵信息和横向 Mascot 视觉，更适合作为当前 `1200x630` 分享预览，本轮不替换。

## 设计要求

- 首屏必须先说明 `RadishX` 和项目矩阵关系，再承载项目内容与角色视觉。
- 桌面端保持强视觉和留白；390px 移动端优先连续阅读，不压缩标题和按钮。
- 标题下不添加解释布局或实现方式的描述型副标题。
- 项目索引使用原生按钮语义并保留可见焦点，移动端允许横向扫读。
- 任何新增图片必须能在移动端完整展示主体，不能裁掉角色或关键 UI。
