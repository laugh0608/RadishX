# 07 布局与平台适配

## 1. 布局模式库

| 模式 | 结构 | 适用 |
| --- | --- | --- |
| 工作台三栏 | 侧栏导航 + 主内容 + 右辅助栏（readiness / 证据 / 属性） | 审计、编辑、检查器与详情场景 |
| 侧栏 + 主区 | 侧栏导航 + KPI 行 + 主表格 / 卡片流 | 通用管理与列表页（ref-03/06/07） |
| 画布优先 | 顶部命令区 + 左对象库 + 中央画布 + 右检查器 + 底部消息 / 结果 | 流程、节点、图形与空间编辑器 |
| 内容流 | 顶导航 + 单列 / 双列内容流 + 可选侧栏 | 社区、文章与文档阅读 |
| 展示分段 | 全宽分段 band 纵向叙事 | 官网、品牌页与营销页 |
| 设置页 | 左设置导航 + 右表单分区 | 通用设置界面（ref-05） |

通用规则：画布类产品中画布必须是最大且最清晰区域；侧栏与辅助栏职责稳定，不混装。

## 2. 断点与基准视口

| 名称 | 范围 | 备注 |
| --- | --- | --- |
| mobile | < 768px | 单列；基准视口 390×844 |
| tablet | 768–1079px | 可保留双栏；基准 768×1024 |
| desktop | 1080–1439px | 完整布局最低档 |
| wide | ≥ 1440px | 基准 1440×900；超宽 1728×1117 校验 |

桌面客户端可用 1920×1080 作为基准；窄屏或竖屏稿可用 1080×1920 作为基准。

## 3. 响应式规则

- PC 与移动是一等目标；页面首版必须同时可用，不把响应式留到最后补救。
- 窄屏是**单列重排**，不是桌面缩放：按「标题与状态 → 关键指标 → 主内容 → 辅助信息」重新排序。
- 移动端：侧栏转抽屉或底部导航（底部导航 ≤ 5 项）；表格降级为卡片列表或横向滚动 + 冻结首列。
- 触控目标 ≥ 44px；纹样与背景装饰在移动端降密或隐藏。
- 任何文本不得溢出、遮挡图片主体或相邻内容；长 id / 路径断行或截断。

## 4. 平台适配

不同平台可采用不同技术映射；本节只描述通用视觉与可访问性原则，不规定具体仓库的接入方式。

### Web（React / Vite 等）

- 可直接使用 `tokens/tokens.css`，也可从 `tokens.json` 生成本地语义层。
- 组件应消费语义 token；深浅主题的属性名和状态管理方式由实现自行决定。

### 桌面客户端 — Webview 壳（Tauri）

- 窗口 chrome 遵循系统惯例；自绘时可用 4px 微倒角与弱对比控制钮。

### 桌面客户端 — 自绘 UI（egui / Rust）

- 可将 tokens.json 映射为样式结构体，保持颜色、圆角和间距语义对应。
- 可打包界面字体保证跨平台中文渲染；画布图元等领域视觉由实现自行定义。

### 移动 / 跨平台管理端（Flutter）

- 可将 tokens.json 映射为 `ThemeData` / 自定义 `ThemeExtension`，避免色值散落组件。
- 触控优先；底部导航 ≤ 5 项；建议提供系统亮暗适配。

### 游戏（Godot）

- 保持 success / warning / danger / info / neutral 的含义稳定，并使用图标、颜色与文字多通道表达。
- HUD、基地面板、地图等沉浸式视觉由具体游戏风格决定，同时维持字号、对比度与色盲冗余底线。

### 输入法候选窗与平台薄壳

- 保持极简、安静，不与宿主应用抢视觉；候选高亮可映射 `--rd-action-soft` 语义；字号可调并跟随系统亮暗。
- IMK、Fcitx5、TSF、Android IME 等窗口形态优先遵循平台惯例。

## 5. 视觉验收基线

- 至少检查一个桌面视口和一个移动 / 窄屏视口。
- 状态色只用于状态语义；同屏强色 ≤ 2 组。
- 无文本溢出、遮挡、错位；中英切换与长名称不引起布局跳动。
- 禁用与阻断有原因说明；未实现能力未被画成可执行入口。
- `prefers-reduced-motion` 生效。
