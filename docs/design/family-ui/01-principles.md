# 01 设计原则

## 家族叙事

Radish 家族产品覆盖社区、游戏、工程软件、AI 工作台、输入法和官网。统一规范的目标不是让它们长得一样，而是让它们**一眼可辨认属于同一家族**：同一套纸墨印色的色彩语言、同一套状态语义、同一种克制清晰的结构观。

合成公式：**现代工作台骨架 × 纸墨印色气质**。

- 骨架（结构、密度、组件形态、状态表达）取自现代清爽工作台语言，见 [references.md](references.md)。
- 气质（色彩、纸感、留白、印色、少量衬线与纹样）取自 Radish 配色母板与淡雅新中式基线。
- 结果应当是：一眼看是现代好用的软件，细看有东方温度；不是把参考图换个色相，也不是把纹样贴进仪表盘。

## 气质关键词

温润、克制、留白、纸感、印色感、低饱和、清晰、状态明确、密度有序、工程可信。

## 设计原则

1. **先结构，后装饰**：页面先保证结构、层级、可读性与交互状态清晰，装饰只增添气质，不承担信息结构。
2. **阅读优先**：长时间阅读与交互界面（论坛、文档、表格、编辑器）的正文可读性、表单清晰度、状态对比度优先于一切装饰。
3. **状态优先且语义化**：每个界面先回答「当前状态是什么、可信到什么程度、下一步能做什么」；状态色只表达状态，不作装饰。
4. **密度有序**：允许高信息密度，但主区、辅助区、诊断区必须层级清楚；同屏强强调色不超过两组。
5. **装饰退后一级**：纹样、纸感、边饰的视觉强度必须低于正文与边框；工作面默认无纹样。
6. **先 token 后颜色**：组件只消费 L1 语义 token；新增 token 必须先在规范中定义语义，再进入实现；不在组件里散落硬编码值。
7. **通用为底，差异有界**：家族识别层必须一致，项目差异必须显式声明（见下节），不允许静默分叉。
8. **亮暗与无障碍从起点考虑**：颜色之外必须有图标、形状或文字第二通道；对比度、触控目标、`prefers-reduced-motion` 是底线不是优化项。

## 避免方向（全家族）

- 大面积紫蓝渐变、装饰光斑、渐变球、bokeh 背景。
- 深色监控大屏作为默认基调（暗色是主题选项，不是气质）。
- 红金国潮、厚重宫廷化、复古旧物感、满屏传统纹样。
- 互联网默认荧光状态色、塑料高光、夸张渐变按钮。
- 营销式 hero、宽幅能力 band 进入工作面。
- 卡片套卡片、双层大白框浮层。
- 把未实现能力画成可点击执行路径。
- 用装饰替代真实内容与真实资产。

## 通用与差异的边界

这是本规范的核心治理设定，与 [README.md](README.md) 的合规三档对应。

### 必须一致（家族识别层）

- L0 配色母板与 L1 语义 token 命名（[02-color.md](02-color.md)）。
- 状态色语义：success / warning / danger / info / neutral 的含义与用法纪律。
- 字体策略与衬线使用边界（[03-typography.md](03-typography.md)）。
- 图标风格基线与「颜色 + 图标 / 文字」双通道原则（[08-brand-assets.md](08-brand-assets.md)）。
- Mascot「萝小白」使用边界（[08-brand-assets.md](08-brand-assets.md)）。
- 上述避免方向清单。

### 允许不同（项目身份层）

- 气质强度：同一 token 底座下，Brand 面纸感浓、Workbench 面近白、Game 面自治。
- 密度与圆角档位：在规范阶梯内按 Profile 选档。
- 项目 accent 分工：从母板中选取，登记于 [02-color.md](02-color.md)。
- 领域组件：画布图元（Flow / Mind designer）、游戏 HUD（Catalyst）、候选窗（Lex）、治理证据面板（Mind）等，由项目差异附录约束。

### 扩展规则（未来新产品）

新产品接入时依次回答三个问题，写入其差异附录（模板见 [10-migration-playbook.md](10-migration-playbook.md)）：

1. 属于哪个 Profile（或声明新 Profile 并回填本规范）。
2. 从母板选哪两组色做主 / 辅 accent（不与近邻产品撞色，登记回 02 章）。
3. 哪些领域组件超出本规范范围、需要项目自治。

新 Profile、新 token、新组件形态一律**先改本规范，再进实现**。
