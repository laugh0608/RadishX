# 视觉与前端规范

本文定义 RadishX 官网的视觉基线、前端表现规则和 Pencil 设计约束。后续官网设计稿和 React 实现应优先遵守本文。

## 与家族统一 UI 规范的关系

`docs/design/family-ui/` 提供通用 UI / 视觉原则、参考 token、组件形态与 UI 参考。本文是 RadishX 官网作为 **Brand 展示面** 的站点级应用与补充，负责官网页面节奏、品牌用色、Mascot 页 / About 页结构与素材约定。family-ui 不为具体项目分配颜色或跟踪采用进度；RadishX 的技术映射和已知差异见 [ui-addendum.md](ui-addendum.md)。

2026-07-31 起，family-ui 默认品牌参考改为灰玉；RadishX 先在 `radishx-site-v1.pen` 完成单页评审，React 实现暂时保留 v26.7.2 胭脂基线，待设计确认后再迁移。

## 参考来源

RadishX 的视觉方向综合以下来源：

- Apple 官网：大幅视觉、少文案、明确节奏、每屏只强调一个核心信息。
- Radish 古风视觉规范：温润、克制、留白、纸感、印色感、低饱和、轻纹样。
- Radish 配色母板：浅纸色、胭脂红、玉青、墨蓝、赭石、雅紫等人民币纸币色系提炼。
- MiMo Code 页面：现代 UI 与淡雅东方视觉结合的处理方式，例如居中首屏、命令条、横向图文 band、水墨背景和轻浮层截图。
- RadishFlow / RadishMind：项目详情页需要保留工程可信感、状态明确和可扫读信息层级。

参考关系是“吸收原则”，不是复制页面、图标、配色、截图或文案。

## 总体气质

RadishX 是 Radish 系列项目矩阵官网，第一版应是创意品牌 / 游戏感 / 视觉冲击和淡雅新中式气质的结合。

关键词：

- 创意品牌
- 项目矩阵
- 萝卜 IP
- 淡雅新中式
- 纸感和留白
- 低饱和但有焦点
- 轻游戏感
- 工程可信

需要避免：

- 把官网做成管理后台。
- 把官网做成 Radish WebOS 桌面复刻。
- 把古风做成厚重宫廷、红金国潮或复古旧物感。
- 使用大面积单一绿色、米色、棕色、紫蓝渐变或深色科技风。
- 用装饰替代真实项目、角色或截图内容。
- 在移动端保留过密纹样导致阅读负担。

## 视觉原则

### 先结构，后装饰

页面首先要清楚说明 RadishX 是什么、各项目是什么、下一步能去哪里。纹样、笔触、纸感和角色图只增强气质，不承担信息结构。

### 强视觉但低噪音

首页可以比项目页更有冲击力，但同一屏只能有一个主视觉焦点。项目详情页应更克制，优先让定位、状态、GitHub、未来域名和关键能力可读。

### 古风是气质，不是符号堆叠

允许使用低透明水墨、云纹、水纹、折枝、纸张肌理和印色感；不使用满屏传统纹样、金色描边、复杂边框或大红大绿装饰。

### 真实资产优先

首页、项目页和 Mascot 页应优先使用真实项目截图、Logo、角色图或经过审核的候选素材。没有审核通过的素材时，设计稿可以使用明确标注的占位区域，但实现不应上线空泛占位图。

第一版项目详情页暂不放真实截图和视频素材；主视觉区域可以使用图形化候选媒体框、项目状态信息和代码内文字 / CSS 临时项目标识。这些标识只作为官网信息识别，不是正式 Logo，后续在各项目有稳定素材后替换。

Pencil 评审稿可以使用明确登记的生成式候选视觉探索构图，但候选必须留在 `assets/` 与设计源范围；未重新审核前不得进入 `public/` 或 React 实现。

## craft 视觉手法（v1.2 基线）

v1.2 设计源确立官网 Brand 面的 craft 手感：以留白、去框和柔投影分层承载结构，强调色高度克制。以下为可执行口径，实现与后续设计稿以此为准；落地进度见 [craft-visual-refresh.md](../features/craft-visual-refresh.md)。

- 去框优先：容器默认不用 1px 描边；分区靠留白 + 背景明度差；卡片 / 浮层用柔投影（elevation）表达层级，而非边框。仅在输入、次级 ghost 按钮等必要处用弱边框。
- 柔投影分层：卡片 `y 12–16 / blur 24–40 / spread 负值 / 暖黑低透` 一档；浮层更强一档；暗色下投影转纯黑并加深。
- 留白节奏：section 纵向 padding 桌面约 88、hero 约 92，移动按比例收敛；一屏一个强焦点，其余安静。
- 圆角：卡片 12–20，控件 pill；不用小于 8 的硬角堆叠。
- 强调色克制：v1 方向以灰玉承担主 CTA 与极小识别点，胭脂降为印章式点缀；页面不做大面积单一绿色，项目色只作小色点。
- 主题切换：header 用三段段控（跟随系统 / 浅色 / 深色），active 段以浮起（surface + 柔投影）表达。
- 标题层级：标题独立成立，不在其下追加解释布局、实现方式或页面职责的描述型副标题；确有必要的背景说明应进入正文内容区。
- 项目矩阵：v1 新方向使用不对称生态图谱，为五个项目分别建立社区轨道、工业场景、流程蓝图、节点星图和中文输入路径；不再把五项内容套进重复横向 band。现有 React band 保留为 v1.2 craft 历史实现基线，等待评审后再决定是否迁移。
- Mascot 舞台：优先采用透明立绘、背景大字和矢量轨道形成单一强焦点，不把角色缩进普通白底图片框。
- primary 按钮：v1 亮色使用深灰玉 + 暖白字；暗色使用提亮灰玉 + 深墨字，前景由 `text-on-brand` 决定。
- 移动端：同一手感下降密度，band 与卡片改单列，触控目标不小于 `44px`，投影与留白按比例收敛。

避免：满屏描边卡片、卡中卡、高饱和整块强调、密排无呼吸的仪表盘式布局。

## 页面节奏

首页建议采用强视觉分段：

1. 首屏：RadishX 品牌名、项目矩阵定位、少量入口按钮、角色或项目矩阵主视觉。
2. 项目矩阵：用不对称生态图谱呈现，每个项目使用与自身领域相关的独立视觉语法，而不是普通卡片堆叠或重复横向 band。
3. 生态关系：说明 Radish、Catalyst、Flow、Mind 的角色分工。
4. Mascot 入口：虚拟形象“萝小白”作为品牌记忆点，使用透明立绘和场景化排版形成独立舞台。
5. About / GitHub：收束到联系、仓库和组织说明。

项目详情页建议结构：

1. 项目名和一句核心定位。
2. 项目视觉区域：第一版使用图形化候选媒体框、状态信息和代码内临时项目标识，后续替换为真实截图、独立 Logo 或领域视觉。
3. 关键能力和当前状态。
4. GitHub 链接、未来独立域名和 Coming Soon 状态。
5. 与 RadishX 项目矩阵的关系。

Mascot 页建议结构：

1. “萝小白”三种形态总览：原始形象、可爱Q版、虚拟形象完全体。
2. 每个形态的设定说明和主图。
3. 表情包 / 服装 / 节日素材 Gallery。
4. 使用说明、版权提示和可爱Q版安全口径。

About 页建议结构：

1. RadishX 组织说明。
2. 联系方式：QQ、邮箱、GitHub、个人主页。
3. 微信公众号二维码和说明。
4. 五个 GitHub 仓库入口。

### 项目色彩分工

以下只描述 RadishX 官网内用于区分项目内容的展示色，不约束对应项目自身的品牌或 UI 配色：

- Radish：胭脂红 + 玉青 + 墨蓝，突出社区、WebOS 和内容生态。
- RadishCatalyst：赭石 + 胭脂红 + 暖纸色，突出游戏、异星工业和角色探索。
- RadishFlow：墨蓝 + 工程蓝灰 + 浅纸色，突出流程模拟、画布和工程可信感。
- RadishMind：墨蓝 + 玉青 + 雅紫小面积点缀，突出智能层、评测、工具编排和审计感。

规则：

- 大面积背景优先使用纸色、暖白、浅灰，不直接满铺品牌红或萝卜绿。
- 同一屏强强调色不超过两组。
- 状态色只表达状态，不作为装饰色。
- 深色区域可以出现，但不作为全站默认基调。

## 字体与排版

- 中文正文优先使用系统无衬线：`PingFang SC`、`Microsoft YaHei UI`、`Noto Sans SC`、系统 sans-serif。
- 中文大标题可小面积使用系统衬线：`Songti SC`、`STSong`、`Noto Serif SC`、serif。
- 英文品牌名使用现代无衬线；代码、命令和域名使用等宽字体。
- 不使用负 `letter-spacing`。
- 不用 `vw` 直接控制字体大小。
- 移动端标题使用独立字号，不靠桌面字号硬缩放。
- 中文标题可以有轻微字距，但不把每个汉字拆成断裂式排版；移动端优先可读性。

建议字号层级：

| 场景 | Desktop | Mobile |
| --- | ---: | ---: |
| 首页 H1 | 64-88 px | 42-52 px |
| 页面 H1 | 48-64 px | 34-42 px |
| Section 标题 | 32-44 px | 26-32 px |
| 卡片 / band 标题 | 22-32 px | 22-28 px |
| 正文 | 16-18 px | 15-16 px |
| 元信息 / chip | 12-14 px | 12-13 px |

## 纹样与背景

推荐类型：

- 水墨晕染。
- 云纹、水纹、山纹。
- 折枝、竹枝、叶片和极淡花枝。
- 萝卜 IP 线稿或剪影。
- 低透明纸张纹理。

允许位置：

- Hero 背景的次级层。
- 项目图谱模块的负空间、矢量路径或领域视觉背后。
- Mascot 页角色图周围。
- 页脚或 About 的收束背景。
- 空状态或轻提示区域。

禁止位置：

- 长篇正文主阅读区。
- 表单输入框内部。
- 按钮文字底下。
- 密集列表、表格和二维码底层。
- 移动端整屏重复平铺。

实现规则：

- 纹样透明度通常控制在 `0.05-0.16`。
- 纹样线条应弱于正文和边框。
- 移动端减少或隐藏复杂纹样。
- 不使用离散装饰光球、渐变球、bokeh 背景。

## 组件表现

### 顶部导航

- 桌面端使用轻量横向导航：RadishX、Projects、Mascot、About、GitHub。
- 窄屏端折叠为紧凑导航或顶部菜单，不能挤压主标题。
- 导航背景可以是半透明纸色，但不要强玻璃拟态。

### 按钮和链接

- 主 CTA 使用深色或品牌色，小面积突出。
- 次级 CTA 使用细描边或柔底样式。
- 项目未上线时，“访问项目”展示 Coming Soon 或禁用态，不伪装成可访问入口。
- 外链需要明确视觉状态，GitHub 链接优先可见。

### 命令条 / 信息条

可以参考 MiMo Code 的命令行条，但 RadishX 不需要安装命令。可用于：

- 展示 `radishx.com`。
- 展示 GitHub 仓库路径。
- 展示项目未来域名。

命令条应是信息展示或复制辅助，不成为主导航替代。

### 项目 Band

- 首页项目矩阵优先使用横向大 band，桌面端图文左右交替。
- 每个 band 包含：项目名、短定位、状态 chip、GitHub / 未来域名入口、主视觉区域。
- 移动端改为单列，图在上或下都可以，但同一页面保持一致节奏。
- band 不是厚重卡片，不做卡片套卡片。

### 媒体框

- 截图和角色图可以使用轻阴影和 6-8px 圆角。
- 图片容器必须设置稳定比例或尺寸约束。
- 不裁掉角色主体和关键 UI 信息。
- 未审核的素材不能进入正式页面实现。

### 标签与状态

- 状态 chip 使用短文案：`GitHub`、`Preview`、`Coming Soon`、`Source Available`、`Vercel`。
- chip 使用低饱和浅底 + 深字，不使用高饱和整块色。

### Gallery

- Mascot Gallery 可使用轻量网格。
- 可爱Q版只使用安全候选图或已审核素材。
- 不提供素材下载入口，除非版权口径另行确认。

## 图片使用

正式写入页面前，必须先确认具体选图。

推荐用途：

- 首页主视觉：优先使用可爱Q版或虚拟形象完全体设定图中的长期稳定素材，也可以使用项目矩阵合成视觉。
- Mascot 页：完整展示“萝小白”三种形态和设定图。
- 项目详情页：第一版暂不放真实截图和视频素材，使用图形化候选媒体框和代码内文字 / CSS 临时项目标识；这些标识不进入素材库、不声明为正式 Logo，后续再替换为对应项目真实截图、独立 Logo 或关键视觉。
- 节日图：只用于活动 Banner 或节日彩蛋，不作为长期默认主视觉。

实现要求：

- 设置 `alt` 文案。
- 设置 `width` / `height` 或稳定 `aspect-ratio`。
- 移动端裁切必须检查主体是否完整。
- 不使用过暗、过糊、主体被裁掉的图片作为首屏核心视觉。
- 不对原始素材做批量压缩、裁切、重采样或覆盖，除非用户确认。

## 响应式视觉规则

默认视口：

- Mobile：`390 x 844`
- Tablet：`768 x 1024`
- Desktop：`1440 x 900`
- Wide：`1728 x 1117`

规则：

- PC 和移动端都是一等目标。
- 首页首屏在移动端仍应能看到品牌、定位和至少一个主入口。
- v1 项目生态图谱在移动端按 Radish、RadishCatalyst、RadishFlow、RadishMind、RadishLex 的叙事顺序改单列；现有 React band 同样保持单列，按钮可换行但不能溢出。
- 纹样、背景图和浮层在移动端降低密度。
- 触控目标不小于 `44px`。
- 任何文本不得遮挡图片主体或相邻内容。

## 动效原则

- 动效服务滚动节奏和内容进入，不制造持续干扰。
- 可使用淡入、轻微位移、轻视差、图片浮层进入。
- 不使用持续抖动、复杂背景动画或影响阅读的循环动效。
- 移动端降低动效强度。
- 必须尊重 `prefers-reduced-motion`。

## Pencil 设计规则

- RadishX 当前新视觉设计稿路径：`docs/design/sources/radishx-site-v1.pen`；`radishx-site-v0.pen` 作为已落地历史基线保留。
- `.pen` 文件只能通过 Pencil MCP 或 Pencil 应用操作，不使用 shell 读取或解析。
- 写入前必须确认 Pencil active editor 是 RadishX 路径，不能误写兄弟项目设计稿。
- 设计稿第一轮至少覆盖：首页桌面版、首页移动版、项目详情模板、Mascot 页和 About 页。
- 设计稿中的未审核图片必须标注为候选，不默认进入正式实现。
- 设计定稿后再初始化或实现对应页面，不跳过视觉基线直接写 UI。
