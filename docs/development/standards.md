# 开发规范

本文定义 RadishX 官网项目的开发规则、响应式要求和验证口径。

## 基础技术栈

- Vite
- React
- TypeScript
- CSS Modules 或普通 CSS，具体实现时优先选择简单、可维护的方案
- 静态站点，部署到 Vercel

## 仓库规则

- 文本文件默认使用 UTF-8、LF 和文件末尾换行。
- Markdown 正文可以保留行尾空格，用于兼容 Markdown 换行。
- 新增文件名优先英文、短横线或小写目录。
- 不提交 `node_modules/`、`dist/`、`.vercel/`、`.env`。
- 候选素材保留在 `assets/`，正式页面使用前必须确认选图。

## React 规则

- 页面组件按页面职责拆分，不把全部页面塞进单个文件。
- 数据常量可以集中在 `src/data/`，项目介绍、链接和域名信息优先结构化维护。
- 组件命名表达真实用途，避免空泛的 `Manager`、`Helper`、`Wrapper`。
- 不提前引入状态管理库；静态官网优先使用 React 自身能力。
- 不提前引入 UI 组件库；只有真实减少复杂度时再考虑。

## 响应式规则

PC 和移动端都是一等目标。

默认视口检查：

- Mobile：`390 x 844`
- Tablet：`768 x 1024`
- Desktop：`1440 x 900`
- Wide：`1728 x 1117`

实现要求：

- 首页、项目页、Mascot 页和 About 页都必须在移动端可完整浏览。
- 导航在窄屏下需要折叠或重排，不能挤压正文。
- 大图必须设置稳定比例或尺寸约束，避免加载后布局跳动。
- 标题、按钮和卡片文字不能溢出容器。
- 不用视口宽度直接缩放字体；使用明确的响应式层级。
- 移动端减少背景纹理、弱化复杂装饰，优先保证内容连续浏览。
- 触控目标建议不小于 `44px`。

## 样式规则

- 优先使用 CSS 变量表达品牌色、文本色、背景色、边框和阴影。
- 不在 JSX 中扩散硬编码颜色、阴影和复杂布局值。
- 视觉装饰应服务内容层级，不压过文案和操作入口。
- 页面 Section 用全宽分区或无框布局承载；卡片只用于项目入口、图库项目或明确的信息单元。
- 不做卡片套卡片。
- 不使用大面积单一色系堆叠，避免页面只剩绿色或米色。

## 链接规则

- 四个项目详情页第一版至少展示 GitHub 链接。
- 未来独立项目域名未上线前，“访问项目”按钮可以禁用或显示 Coming Soon。
- 不把 `hub.radishx.com`、`forge.radishx.com`、`flow.radishx.com`、`mind.radishx.com` 配成本官网 Vercel 路由。

## 验证规则

项目初始化后，默认至少执行：

```bash
npm run build
```

后续可补充：

```bash
npm run lint
npm run type-check
```

涉及 UI、布局或素材改动时，应使用真实浏览器检查桌面和移动端视图。完成前至少确认：

- 首页无明显错位。
- 导航可用。
- 四个项目页入口可访问。
- Mascot 页图片不变形、不遮挡正文。
- About 页二维码和联系方式可读。
