# Agent 协作与执行规则

本文承接 `AGENTS.md`、`CLAUDE.md` 不适合在任务启动时全量加载的协作细则。根入口只保留跨任务、跨阶段且必须立即生效的长期约束；当前状态以[当前规划](../planning/current.md)为准，技术、视觉、素材和部署契约以对应专题文档为准。

## 文档职责与优先级

### 三层职责

| 层级 | 职责 | 典型内容 |
| --- | --- | --- |
| 根入口 | Agent 启动即生效的长期契约 | 授权边界、协作原则、安全红线、任务路由 |
| `docs/` 专题 | 稳定但按任务读取的详细规则 | 开发、视觉、素材、部署、验证、功能边界 |
| 当前规划与记录 | 随阶段变化的状态和事实 | 当前顺位、临时门禁、“当前不做”、验证证据 |

根入口不是项目手册的副本，`docs/README.md` 也不是阶段规则正文。短入口负责告诉读者“去哪里读”，专题文档负责解释“规则是什么”，当前规划与开发日志负责说明“现在处于什么状态、已经发生了什么”。

### 判断顺序

1. 先遵循项目所有者在当前任务中的明确要求。
2. 再遵循 `AGENTS.md` / `CLAUDE.md` 的启动级约束。
3. 根据任务路由读取当前 `docs/` 真相源。
4. 通过代码、测试、配置和验证结果确认实现事实。
5. 文档与实现不一致时，先判断哪一侧过期，并在当前任务范围内统一口径。

## 任务推进流程

### 开始任务

- 先检查工作区状态，确认现有修改、当前分支和任务影响面，不覆盖或混入无关改动。
- 判断任务属于回答、诊断、设计、实现、验证还是发布，不从一个请求推导范围外的写入或外部操作。
- 只读取根入口路由到的必要文档；需要追溯历史事实时，再进入 feature 完成记录或 `docs/devlogs/`。
- 涉及当前阶段、优先级或下一顺位时，默认先读 `docs/planning/current.md`，不从旧周志反推当前计划。

### 方案与确认

- 架构、规则、接口、依赖、部署、运行时行为或范围不清的变更，在实施前说明目标、边界、影响和验证方式并等待确认。
- 项目所有者明确要求直接修改且范围清晰、风险可控时，直接实施。
- 小规模、低风险、需求明确的文档、配置或素材整理变更可以直接实施。
- 不同合理解释会造成明显不同的页面行为、数据结构、兼容边界、素材授权或外部影响时，先澄清再修改。
- 已确认方案若出现实质性范围变化，应暂停扩张并重新确认。

### 实现与收口

- 优先治理根因和同类问题，不用默认值、静默降级或重复兜底掩盖真实契约问题。
- 不做与当前目标无关的重构；遇到直接阻碍目标的结构问题时，进行必要且边界清楚的修正。
- 抽象必须服务于真实复用、边界隔离、复杂度下降或契约稳定。
- 交付时说明完成内容、验证结果和仍未验证的真实风险，不把未执行的浏览器或线上检查写成已通过。

## 设计先行与内容归位

- 新增或重做页面、长期功能、较大视觉调整、素材替换和发布检查目标时，先创建或更新对应 `docs/features/*.md`。
- 小规模 bug、低风险文案或样式调整、纯清理和不改变功能边界的验证补漏，不强制新建 feature 文档；若暴露说明与实现不一致，应同步修正文档真相源。
- `docs/planning/current.md` 只承载当前阶段、活跃目标、执行顺序、停止线和跨目标风险。
- `docs/features/` 承载目标背景、范围、不做项、设计要求、开发任务、验证、完成标准和后续事项。
- `docs/development/`、`docs/design/`、`docs/assets/` 与 `docs/deployment/` 承载跨目标复用的稳定规则。
- `docs/devlogs/` 记录已经完成的结果、关键决策、验证证据和遗留风险，不作为当前计划或长期规则真相源。
- `README.md` 面向项目读者提供稳定项目概览；`docs/README.md` 只提供文档地图和分层说明，不复制当前规划正文。

发生变化时按主题更新真相源：

| 变化 | 更新位置 |
| --- | --- |
| 当前阶段、优先级、临时门禁 | `docs/planning/current.md` |
| 页面、功能、素材替换、发布目标 | 对应 `docs/features/*.md` |
| 工程、响应式、验证、提交规则 | `docs/development/standards.md` |
| 视觉方向、token、Pencil 流程 | `docs/design/` 对应文档 |
| 素材来源、授权、转换、公开使用 | `docs/assets/materials.md` |
| 域名、Vercel、跳转、部署 | `docs/deployment/vercel.md` |
| 已完成结果和验证证据 | `docs/devlogs/YYYY-Www.md` |
| 启动级长期协作契约 | `AGENTS.md` 与 `CLAUDE.md` |

## 授权、运行与外部边界

### 依赖与外部资源

- 安装或更新依赖前，说明具体命令、目标包或版本以及对 `package.json` 和 lockfile 的影响，并取得当前任务授权。
- 引入外部图片、字体、库或第三方服务前，说明来源、用途、许可、维护成本和替代方案。
- 授权只覆盖已经说明的命令和范围；新增依赖、改变版本策略或扩大资源范围时重新确认。

### 服务启动与真实 Smoke

- 启动 `npm run dev`、`npm run preview` 等长期进程前，说明命令、端口、运行方式和清理方式，并取得当前任务授权。
- 不沿用历史会话中的启动状态；真实 HTTP 或浏览器 Smoke 前，重新确认当前任务需要的服务已经启动。
- 本地开发中的代码侧验证优先使用构建、类型检查和定向静态检查；真实浏览器 Smoke 在页面、视觉、交互或发布目标需要时执行。

### 远程与素材操作

- 推送分支、创建远程资源、配置 Vercel、部署或修改 DNS 前，说明目标、影响面和回退方式并取得授权。
- 批量处理素材前，明确输入目录、输出目录、尺寸、格式、质量、覆盖策略和恢复方式；原始素材默认只读保留。
- 读取兄弟项目以确认公开事实或候选来源不等于获得修改权限；默认不得跨工作区写入。

## 验证与留痕

- 按风险选择 `npm run build`、`npm run type-check`、本地发布检查、HTTP Smoke、桌面 / 移动浏览器检查和 `git diff --check`。
- 纯文档变更至少检查入口同步、Markdown 链接与差异卫生；不因未改代码而机械执行浏览器验证。
- 页面、布局、响应式或素材展示变化至少覆盖一个桌面视口和一个移动视口，具体尺寸与检查项以开发规范和目标文档为准。
- 部署与线上检查是独立外部动作，不由本地构建通过自动推导授权。
- 重要推进写入当周开发日志；临时命令输出、截图和流水证据不堆入根入口或 `docs/README.md`。

## 根入口维护规则

一条规则只有同时满足以下条件，才应加入 `AGENTS.md` / `CLAUDE.md`：

1. 跨任务成立，而不是某个页面、功能或批次专属。
2. 跨开发阶段成立，不会随当前里程碑自然失效。
3. 必须在 Agent 读取专题文档前生效，否则容易产生高风险或大范围错误。
4. 无法只通过任务路由和对应 `docs/` 专题可靠承载。

不满足这些条件的内容，应归入专题、当前规划、开发日志或历史记录。

- 两个根入口只允许首段入口说明不同，从第 4 行开始必须完全一致。
- `npm run check:agent-guides` 会检查两份正文同步、UTF-8 BOM、末尾换行和本地 Markdown 链接。
- 修改根入口时同步检查关联 `docs/` 是否仍是真相源；修改阶段状态、临时门禁或设计稿版本时，不应反向更新根入口。
- 根入口目标是保持短、稳定和可路由，建议不超过 `120` 行；超过时优先下沉按任务读取的细则。
